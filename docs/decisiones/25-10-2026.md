# Paginación por cursor

**Fecha:** 2026-10-25

## Problema

Las listas (tareas, comentarios, actividad) van a crecer y el cliente móvil
necesita cargarlas por partes sin que se repitan o se salten elementos cuando
otros usuarios crean datos al mismo tiempo.

## Opciones

- **Offset (`limit` + `offset`):** simple de implementar. (− se desordena con
  datos que cambian y `skip` se vuelve lento en listas grandes)
- **Cursor:** continúa desde un punto fijo. (+ estable con datos vivos,
  - encaja con scroll infinito; − más trabajo al implementarla)

## Decisión

Cursor con forma Relay (`edges`, `pageInfo`), ordenado por `createdAt` e `id`.
La app es colaborativa y las listas cambian mientras se leen.

## Consecuencias

Se necesita un índice en `(createdAt, id)` y que los repositorios devuelvan
`limit + 1` elementos para saber si hay otra página. Las listas pequeñas
(como los miembros de un workspace) quedan sin paginar.

# Errores de negocio en el schema

## Problema

El cliente debe poder distinguir "no puedes hacer esto" de "algo falló",
y reaccionar distinto a cada caso.

## Opciones

- **Solo errores de GraphQL con códigos:** simple. (− sin tipos para el cliente
  y la nulidad puede dejar `data` en `null`)
- **Uniones en el schema (`Task | InvalidTransition | NotAllowed`):** el cliente
  ve los casos posibles. (+ tipos generados, − más boilerplate)

## Decisión

Enfoque híbrido: uniones para errores de negocio que el usuario puede corregir
(`moveTask`, `assignTask`); errores de GraphQL con código para fallos
inesperados y para `UNAUTHENTICATED`.

## Consecuencias

Traduzco los errores de zod a un tipo `ValidationError` en la frontera.
Empiezo solo con las mutaciones que tienen reglas reales.

# Transacciones al borrar proyectos

**Fecha:** 2026-10-25

## Problema

Borrar un proyecto y sus tareas debe ocurrir completo o no ocurrir, sin dejar
tareas huérfanas si algo falla a la mitad.

## Opciones

- **Transacción de MongoDB:** atómica de verdad. (− requiere replica set)
- **Borrado lógico (`deletedAt`):** seguro y reversible. (− cada consulta debe
  recordar el filtro)
- **Borrado en orden con reintento:** sin infraestructura extra. (− sin
  garantía atómica)

## Decisión

Transacción de MongoDB. Configuro un replica set de un solo nodo en desarrollo.

## Consecuencias

Los métodos de los repositorios aceptan una `session` opcional y el caso de uso
abre la transacción. Si luego añado una papelera, combino con borrado lógico.
